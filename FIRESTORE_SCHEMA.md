# ListingMaker — Firestore Schema

Document structure for Firebase Firestore database.

---

## Collection: `profiles`

User profiles with credits and plan information.

**Document ID:** `{uid}` (Firebase Auth user ID)

```typescript
{
  id: string;                    // User ID (same as doc ID)
  email: string;                 // User email
  fullName: string | null;       // User's full name
  creditsRemaining: number;      // Number of listings they can create (starts at 1 free)
  plan: "free" | "starter" | "pro" | "business";
  stripeCustomerId: string | null;  // Stripe customer ID for payments
  createdAt: Timestamp;          // When account was created
  updatedAt: Timestamp;          // Last updated
}
```

**Indices needed:**
- None (queries by document ID only)

**Security Rules:**
- Users can only read/write their own profile

---

## Collection: `users/{uid}/listings`

Listings generated by a user (subcollection under their profile).

**Document ID:** Auto-generated (UUID)

```typescript
{
  id: string;                    // Listing ID
  userId: string;                // User who created it
  productName: string;           // e.g., "Omega-3 Fish Oil"
  brand: string;                 // e.g., "MIWLAB"
  marketplace: string;           // "us" | "uk" | "de" | "fr" | "it" | "es"
  category: string;              // Amazon category
  price: string | null;          // Selling price (if provided)
  title: string;                 // Generated Amazon title (200 chars)
  bullets: string[];             // 5 bullet points (500 chars each)
  description: string;           // Backend description (2000 chars)
  backendKeywords: string;       // Search terms (250 bytes)
  keywordsUsed: {                // Keyword strategy breakdown
    primary: string;
    secondary: string[];
    backend: string[];
  };
  competitorData: string | null; // Raw competitor listings text
  additionalInfo: string | null; // Extra product info user provided
  createdAt: Timestamp;          // When listing was generated
}
```

**Indices needed:**
- Composite: `userId` + `createdAt` (descending) — for dashboard listing history

**Security Rules:**
- Users can only read/write their own listings

---

## Collection: `users/{uid}/purchases`

Purchase history (subcollection under user profile).

**Document ID:** Auto-generated

```typescript
{
  id: string;                    // Purchase ID
  userId: string;                // User ID
  stripeSessionId: string;       // Stripe Checkout session ID
  stripePaymentIntent: string | null;  // Stripe payment intent ID
  plan: "starter" | "pro" | "business";
  creditsAdded: number;          // How many listings they got (5, 10, 25)
  amountCents: number;           // Price in cents ($29 = 2900)
  currency: string;              // "usd" or other
  status: "completed" | "pending" | "failed";
  createdAt: Timestamp;          // When purchase was made
}
```

**Indices needed:**
- Composite: `userId` + `createdAt` (descending) — for purchase history

**Security Rules:**
- Users can only read their own purchases

## Firestore Security Rules

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Profiles: users can read and update their own
    match /profiles/{uid} {
      allow read, update: if request.auth.uid == uid;
      allow create: if request.auth.uid == uid;
    }

    // Listings: users can read, create, and delete their own
    match /users/{uid}/listings/{document=**} {
      allow read, create, delete: if request.auth.uid == uid;
    }

    // Purchases: users can read their own
    match /users/{uid}/purchases/{document=**} {
      allow read: if request.auth.uid == uid;
    }

    // Affiliates: Read-only for authenticated users (to verify codes), write only by Admin
    match /affiliates/{code} {
      allow read: if request.auth != null;
      allow write: if false; // Only via Admin SDK / Webhooks
    }
  }
}
```

## Firebase Authentication Setup

1. Go to **Firebase Console → Authentication → Sign-in method**
2. Enable:
   - Email/Password
   - Google (optional but recommended)
3. Configure OAuth redirect domain (your app domain)

## Creating Test Data (Optional)

To manually create test profiles in the Firebase Console:

1. Go to **Firestore → Collections → profiles**
2. Create a document with a user ID as the document name
3. Add the fields above

Or use the auth flow in the app (signup at `/signup` creates a profile automatically).

## Data Migration from Supabase (If Needed)

If you ever need to migrate from Supabase:

1. Export Supabase tables to CSV/JSON
2. Write a script to transform to Firestore structure
3. Use Firebase Admin SDK to batch import

```typescript
// Example batch import
const db = admin.firestore();
const batch = db.batch();

data.forEach((profile) => {
  const docRef = db.collection("profiles").doc(profile.id);
  batch.set(docRef, profile);
});

await batch.commit();
```
